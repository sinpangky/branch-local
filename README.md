# 枝间 · Branch Local

Windows、macOS（Apple Silicon）和 Linux 桌面 AI 分支对话应用。从回复中的一句话开出新对话，用画布保留每条思路之间的关系。模型由自己的 Ollama 或兼容 OpenAI 的 API 提供。

围绕复杂问题展开多条思路，比较依据，并保存可以追溯的结论。当前版本 **1.5.1** 完善了可选 Agent 的工具、任务指引和执行规则，继续保留直接聊天与统一桌面界面。

## 1.5.1 Agent 操作与执行规则

默认仍使用直接聊天。进入“设置 → Agent”，开启后选择工作目录；在会话输入框的“执行方式”中选择 Agent。第一种执行引擎复用当前配置的本地模型或兼容 API，模型需要支持工具调用。直接聊天不发送工具定义，也不获得文件或命令执行能力。

Agent 可以列出、按行读取和搜索工作目录中的 UTF-8 文件，使用精确文字替换局部编辑，创建文件或单层目录，并按权限调用命令、网页读取、下载和搜索工具。文件写入、目录创建、命令和下载均先展示具体预览，点击“允许此次操作”后才执行；拒绝也会记录并交给模型。局部替换默认只接受唯一匹配，明确指定后才可替换所有匹配。修改已有文件时，批准后若原文已变化，会拒绝覆盖并要求重新读取。结构化工具不提供文件删除，下载不覆盖已有文件，也不会自动打开或执行内容。

命令与网络工具分别默认关闭。**批准的命令以当前系统用户权限运行，工作目录不是操作系统沙箱**，命令也可能访问其他目录或网络；联网开关只限制结构化网络工具。文件工具逐步验证路径，拒绝越界和符号链接，并默认排除依赖、版本库及常见密钥文件。文本文件上限 1 MiB，按行读取默认 200 行、最多 1000 行，单次返回文字最多 80,000 个 UTF-16 字符单元；超长行或行块截断时返回 `next_read` 参数，可直接续读同一块，读完再读取后续行。分段期间应核对文件 hash，避免混合变动前后的内容。下载上限 20 MiB；写入的父目录需要已经存在，可先用 `create_directory` 逐层创建目录。

网页工具仅访问公网 HTTPS，验证 DNS 及每次重定向；不发送模型 API Key。网页搜索需额外配置支持 JSON 的 SearXNG API（例如 `https://search.example/search`），留空时仍可按网址读取和下载，但不提供网页搜索。服务端需要启用 JSON 输出；许多公共实例默认关闭此格式，见 [SearXNG Search API](https://docs.searxng.org/dev/search_api.html)。

### 可执行任务与工具选择

“设置 → Agent → Agent 能做什么”提供折叠指南，按当前设置标记每类任务的工具开放条件；不调用模型或运行命令，也不把打开权限当作已验证环境。常见任务可以这样交给 Agent：

| 任务 | 工具路径与条件 | 示例 |
| --- | --- | --- |
| 项目排查、修改与验证 | `list_files` / `search_files` 定位，`read_file` 分段检查，`edit_file` 精确修改；开启命令权限后用 `run_command` 运行项目已有测试或构建 | 检查启动报错，先找到根因，再做最小修改并运行相关测试；报告实际通过和未通过的检查。 |
| 文档、笔记与资料整理 | 读取、搜索已有文本，使用 `create_directory` / `write_file` 保存整理结果；已有文档优先局部编辑 | 按主题整理 notes 里的 Markdown，保留原始文件路径，并输出尚未确认的内容。 |
| 数据与脚本处理 | 先检查输入样例和本机程序，写入脚本，再申请 `run_command` 执行并检查结果；需要命令权限及对应依赖 | 清理 CSV 中重复行，保留原文件，输出新文件和处理数量，用小样例核对结果。 |
| Git 状态与变更比较 | `run_command` 检查 `git status`、`git diff` 和历史；需要命令权限和可用 Git | 查看当前未提交修改，解释行为变化和潜在问题，不提交、不推送。 |
| 网页研究与文件下载 | 已知网址用 `fetch_url`；发现资料需 `web_search` 和 SearXNG 配置；`download_file` 下载前逐次确认 | 阅读给定的官方文档，列出依据和链接，把需要的公开资料下载到指定子目录。 |

PDF、Office、图像转换与数值分析可通过已安装的 Python、Node.js 或其他命令行程序完成，但并非内置文件工具直接支持的格式。Agent 应先检查程序和依赖是否存在，缺少时说明阻碍；确需安装时先取得相应任务授权，再预览并逐次批准安装命令。网页工具只读取静态文字，不登录、不点击页面，也不执行网页脚本。复杂交互网站和扫描件 OCR 需要额外程序或专用工具。

内置执行规则要求先检查任务相关文件和项目约定，按任务选择工具，控制读取范围，对已有文件优先精确编辑；完成后执行与改动相匹配的验证，区分已完成、未验证和受阻部分。运行命令输出不等于验证通过，测试失败后应根据报错继续定位；被拒绝的操作不能通过另一工具绕过。用户填写的系统提示词继续用于语言、表达和任务偏好，Agent 同时接收内置执行规则。

运行进度、批准／拒绝、工具结果及产物相对路径保存到本地会话记录。切换会话或画布后可以返回正在执行的任务；停止、关闭或切换数据目录会取消模型请求、审批、下载及子进程，并等待清理。应用重新打开、复制或导入仍标记“执行中”的历史时，记录会变为“上次中断”，不会自动续跑。重新运行会保留旧记录并新建运行；已完成的文件修改不会自动撤销，因此继续前需要检查当前状态。

**会话分支独立保存讨论，但共享选定的工作目录；创建分支不会复制或隔离文件。** 分支、合并、总结及直接聊天仍使用原有的文字上下文快照，不继承进程、审批或工具协议状态。同一 Agent 运行内部追加真实工具调用和结果；跨运行只继承可见文字，不保证复用执行引擎的 KV 状态。

后台按模型轮次适配器、运行控制、工具宿主三层组织。当前仅提供 `compatible` 引擎，`createAgentRuntime` 可以注入其他模型轮次适配器；接入拥有独立工具循环的外部 Agent 仍需运行级适配，目前尚未接入 Codex CLI 等外部引擎。工具协议依据 [OpenAI Docs 的工具调用说明](https://developers.openai.com/api/docs/guides/function-calling)及 [Ollama tool calling](https://docs.ollama.com/capabilities/tool-calling)。运行默认最多 12 轮模型请求，可设为 1–30；单次运行最多执行 24 次工具。桌面应用使用内部协议，不需要监听端口；网页开发模式不开放本地 Agent 执行。

## 1.4.1 界面与阅读

浅色与深色主题统一使用中性灰阶，侧栏、画布、阅读面板、设置和研究工具共用控件样式、间距与状态反馈。全局 UI 基准为 14 px，辅助文字基准为 12 px，标题使用 600 字重。新用户会话正文默认为 16 px、1.65 倍行高；已有字号与行高设置保留，可在“阅读”中实时预览和调整。

阅读、分屏和画布模式保持一致的操作入口。搜索结果支持方向键选择、Enter 打开；切换会话后恢复各自的阅读位置。设置固定保留底部保存栏，快捷键支持即时搜索和修改数量提示；模型连接状态依据实际读取的列表，不把填入地址等同于已验证回答能力。

设置分类、主题与快捷键入口参考 [Codex 桌面设置](https://learn.chatgpt.com/docs/app/settings)；控件一致性、状态反馈与排版层次参考 [Microsoft Copilot UI guidelines](https://learn.microsoft.com/en-us/microsoft-365-copilot/extensibility/declarative-agent-ui-widgets-guidelines)。设计追求相近、熟悉的桌面使用体验，并非像素复刻。

`release/SHA256SUMS-1.5.1.txt` 包含本次各安装包的 SHA256，可用 `Get-FileHash`、`shasum -a 256` 或 `sha256sum` 核对。

欢迎画布里的回答是**静态演示**。使用真实 AI 前，请在“设置 → 模型连接”连接模型。

## 从探索到结论

1. 打开不同分支分别深入问题，使用“探索中 / 待验证 / 已采用 / 暂缓”标记研究进展。这些状态由用户指定。
2. 点击画布或会话中的“比较分支”，选择至少两段讨论。当前模型读取所选会话的完整历史，整理共同点、分歧、依据、未决问题与结论；长历史分段处理，不静默截断中间内容。
3. 展开每条依据，可以先看引文和当前原文，再跳到来源消息。服务端会核对引用的节点、消息和原文；没有可验证引用的条目明确提示缺少依据，不能把自动引用当作事实验证。
4. 修改或删选草稿，按自己的判断勾选“我已验证 / 我决定采用”，再保存独立结论卡。AI 不会自动确认。结论卡可以继续编辑、引用、追问及导出 Markdown；修改文字会清除该条原有确认。结论正文分片保存，保留后续追问。

比较结果保存前会再次检查来源。来源讨论被修改、删除或归档后，旧草稿不能直接保存，需要重新比较。关闭比较面板后，可从同一画布入口回到本次尚未保存的草稿；未保存草稿只留在当前应用运行中。

“研究进展”显示上次打开的位置、人工确认的结论和未决事项，可直接继续。上次位置保存在本机应用 profile 中；JSON 迁移后仍可按最后消息时间回看进度。摘要显示更新时间；消息、继承历史或相关结构变化后提示可能过期，用户可更新。此提示不代表内容已经被核实。

未连接模型时，进入“研究进展 → 离线体验完整流程”，可以在明确标记的静态演示中体验分支比较、引用和结论保存；不会自动请求模型。点击“生成比较”、发送新问题或手动生成摘要属于真实模型操作。

## 选择下一次回答的上下文

输入框工具栏提供三种方式，可预览实际的消息角色和完整文本，以及当前系统提示词与草稿：

- **完整历史：** 使用原来的继承快照和本会话内容，保持分支请求前缀。
- **关键结论：** 仅带入明确勾选的结论卡中已经人工验证或采用的条目，以及当前会话自己的消息。其他结论卡不自动加入。
- **指定消息：** 仅带入勾选的继承历史或本会话消息，发送时始终加入当前新问题一次。失效的选择会提示，不会猜测替代内容。

改变策略会改变模型可见的背景，也可能减少 KV 前缀缓存的复用。它不会删除本地历史。从使用筛选策略的父会话创建分支时，新快照遵守该策略，避免重新带入已排除的历史。比较和合并仍以用户选中的来源会话完整历史为对象；追加到使用筛选策略的主干后，需要检查下一次请求是否包含新资料。

## 本地材料

在会话输入框点击“添加资料”，通过原生对话框导入 Markdown、TXT 或可提取文字的 PDF。PDF 保留页码，长文本按块保存为带来源标签的消息；概览可查材料名称、页码和分段数。原文件不复制进工作区，保存的是提取文字，工作区导出也包含这些文字。

提取在本机执行；扫描图片 PDF 当前不支持 OCR，加密或解析失败会明确报错。一次最多 20 个文件、单文件 20 MiB、累计提取文字 1 MiB、PDF 总计 500 页；超限整批失败，不静默丢页。PDF 提取可能改变视觉排版，重要公式、表格与页内阅读顺序仍应对照原文件。

导入动作只读取并保存本地文字。含资料及继承资料的分支默认不参与自动摘要，单纯导航不会触发资料摘要。主动回答、生成摘要或比较会把所需内容交给配置的模型；使用远程 API 时，这些内容会离开本机。可以在“生成与总结 → 允许本地资料参与自动摘要”明确开启，并使用上下文选择限定下一次回答的材料。

## 分支和画布

点击卡片打开对话；在消息中选中文字，点击浮出的“从选中文字分支”，即可沿这段内容创建子对话。每条消息下也可以直接“从这里分支”。

新分支继承父对话截至所选消息的**创建时上下文快照**。选中文字、表格或图片用于定位和聚焦，继承范围包含其所在的完整消息，以保留原消息和格式。父对话后续消息、兄弟分支和之后对父消息的编辑不会混入已有快照。展开面板中的“继承上下文”可以检查实际内容。

每个来源位置附近和消息下方显示已有分支链接；分支中的“定位父对话中的来源”会返回原消息并高亮具体片段，重复句子按创建时选中的一处定位。表格、图片有独立的分支按钮。原消息被编辑或删除后，打开保存的历史快照，不猜测当前位置。

对话标题栏的“切换会话概览”展开模型总结、文中来源、父分支、派生分支、合并来源和去向。来源仅提取对话实际出现的链接，不代表模型或应用已访问它们；浏览概览与跳转不会请求模型。最近一条回答的用量来自服务端实际报告，未报告的缓存读取显示未知。

已实现：

- 多画布，新建、重命名、复制、归档和回收站；删除可以恢复，也可以在回收站确认永久删除。
- 多层分支、折叠和展开、复制整个子树、归档/删除子树及撤销最近一次操作。
- 合并时可新建会话，或选择已有会话作为主干。保留主干原有消息，只把其他来源的不同后续内容以引用资料追加；去重共同连续前缀，重复追加跳过已合入的历史，来源增长后仅添加新后续。编辑或回滚来源时从变化处重新引用，不做语义去重。保留来源记录及合并连线。
- 左侧分支目录、跨画布全文搜索（含继承上下文和总结）、缩略地图、节点居中和自动排列。
- 拖动卡片标题移动节点、拖动画布平移、滚轮缩放及适应全图。
- 默认在新建会话、分支或结论卡时自动布局，可在交互设置关闭；“聚焦当前路径”淡化其他卡片，缩小时减少细节并突出方向和结论。
- 每张卡片可以单独拖动右下角调宽高，尺寸自动保存；聚焦右下角后可用方向键微调，按 Home 恢复该卡片默认大小。连线、缩略图和自动排列适配各自尺寸。
- 卡片生成、连线高亮、视口移动、自动排列、面板及菜单开合动画；系统开启减少动画时相应简化。
- Markdown 标题、加粗、列表、表格、代码高亮与复制，以及本地 KaTeX 公式渲染，支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。
- Markdown 图片显示来源占位，不自动请求外部资源；HTTPS 图片点击后加载，HTTP 图片提供外链。图片分支保存链接和说明用于定位，当前文字模型接口不发送图片像素。
- 会话面板拖动左边缘调宽，支持键盘方向键调整及展开阅读；字号、行高、代码换行均可配置。
- 消息复制与编辑、流式输出、停止生成和重新生成最后回答。
- 原生文件对话框导入/导出 JSON 工作区、导出当前分支为 Markdown。导入作为新画布加入，不覆盖原画布；文件上限 64 MiB，并验证总节点、消息与文本大小。

重新生成会排除被替换的回答，成功后沿用原消息 ID，保留已有分支锚点；失败时保留原回答及已收到的新内容。已有分支的快照不随重生成改变。

## 分支总结与设置

卡片优先显示模型生成的标题和总结，下面附问题与回答摘录。首轮回答完成、建立新分支或合并时，后台使用当前配置的本地模型或 API 生成总结；创建分支时也更新父分支。可以在对话标题下或卡片菜单中手动更新，失败时可以重试。

总结会包含完整继承上下文、本分支消息、分支树的主干/中间/叶子位置、父子和合并关系，以及关联分支已有的总结，帮助模型区分不同方向。长历史先分段概括，再综合；总结不会只取消息开头或末尾。总结任务按顺序运行，新对话生成优先；生成途中内容变化时会丢弃旧结果并有限重试。

“设置”包含模型连接、阅读、交互、生成与总结、本地数据、快捷键六类设置。支持主题、字号/行高、代码换行、默认面板宽度、发送按键、缩略图、减少动画、总结开关与字数、回答 token 上限、超时、系统提示词和温度。API 提供方可能不支持某些生成参数，实际兼容性以其服务为准。

## 连接模型

### 本机 Ollama

安装 [Ollama](https://ollama.com/)，下载一个适合自己硬件的模型，例如：

```powershell
ollama pull qwen3:8b
```

Ollama 桌面程序通常已运行服务。若没有运行，可用 `ollama serve` 启动；已运行时无需重复执行。

在“模型与偏好”选择“本机 Ollama”，填写：

| 设置         | 值                             |
| ------------ | ------------------------------ |
| API Base URL | `http://127.0.0.1:11434/v1`    |
| 模型名称     | `qwen3:8b`，或自己下载的模型名 |
| API Key      | 留空                           |

“读取模型”可以检查连接并获取模型列表。首次下载模型需要网络；模型准备好后，使用本机 Ollama 可以离线运行。默认模型不保证适合所有电脑。

### 兼容 OpenAI 的 API

填写提供方的 Base URL、模型名称和 API Key。Base URL 通常到 `/v1`，不要附加 `/chat/completions`；具体前缀以提供方文档为准。

应用请求 `GET {baseUrl}/models` 和 `POST {baseUrl}/chat/completions`，支持 SSE 和兼容的非流式 JSON 回答。提供方不支持模型列表时，可以手动填写模型。系统提示词和 Temperature 在模型设置中配置。

使用远程 API 时，对话请求发送当前分支上下文；启用总结后，总结请求还会发送当前画布的分支关系和关联总结，可能产生 API 费用。ChatGPT 订阅登录尚未实现，需要自行配置模型服务。

### 分支与 KV cache

本地 fork 保存对话历史，并不复制模型服务器的 KV cache。新分支保持原始角色、消息顺序和文本前缀，选中内容的聚焦提示放入分支第一条新问题；普通对话请求不会加入动态分支树、邻居总结等资料。旧版已保存的聚焦提示保持原语义，以免改变既有会话。

整表按钮建立的新分支以表格序号和首行短摘录聚焦，完整表格仍只存在于继承历史；界面保留完整引用用于原文定位。手动选中的局部文字保留精确引用。

当前使用无状态 Chat Completions 接口，仍需发送完整历史。相同前缀可以让支持缓存的服务器复用已有 KV，减少重复预填充计算；能否命中受模型、模板、路由、缓存保留和服务端配置影响。缓存不等于输入 tokens 为零，也不保证免费。两个分叉后的 KV 不能直接拼接，另一分支追加的差异仍需要作为新输入处理；保留主干前缀可避免重写主干历史。

自动总结是独立的模型请求；可在设置中关闭。用量中未知的缓存数量不会推断成零或命中。兼容网关、Ollama、vLLM 的实际缓存能力与计费以各自服务为准，应用不会强行加入不受支持的会话参数。

参考：[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[OpenAI Conversation state](https://developers.openai.com/api/docs/guides/conversation-state)、[vLLM Automatic Prefix Caching](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)。

## 数据与密钥

桌面版默认 profile 目录在 Windows 是 `%APPDATA%\BranchLocal`，macOS 是 `~/Library/Application Support/BranchLocal`，Linux 是 `${XDG_CONFIG_HOME:-~/.config}/BranchLocal`。默认数据保存在 profile 下的 `data/`，目录选择保存在 `storage.json`，可在“设置 → 本地数据”打开或更改。可以把当前数据复制到空目录，也可以载入已有有效工作区的目录；切换前会停止生成并保存，原目录保留，不覆盖目标已有内容。安装版、免安装版和源码桌面版默认共享这一配置；卸载应用不会主动删除数据。未选择记住的 API Key 仅在本次连接的内存中，更换数据目录后需重新填写。

| 文件                    | 内容                             |
| ----------------------- | -------------------------------- |
| `workspace.json`        | 画布、消息、分支/合并快照、总结、归档/回收站、草稿和视口 |
| `workspace.json.backup` | 上一次成功保存前的备份           |
| `settings.json`         | 模型设置及选择记住的加密密钥     |

工作区通过临时文件原子替换，主文件损坏时会尝试备份。备份不是完整版本历史，重要内容请定期导出。旧项目 `data/` 会在第一次从本项目启动桌面版时迁移；原文件保持不变，已有桌面数据不会被覆盖。本机交付已执行此迁移，其他电脑可用工作区 JSON 导入。

API Key 默认仅保留在应用本次运行的内存中。勾选“记住密钥”后，使用 Electron safeStorage 保存：Windows 使用系统用户加密，macOS 使用 Keychain，Linux 使用 GNOME Keyring 或 KWallet。设置文件不保存明文 API Key，也不使用 Linux 的 `basic_text` 后备模式。旧明文设置迁入桌面版时会转换为加密字段；加密失败会保留原文件并报告错误。密钥存储机制见 [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

工作区 JSON 和 Markdown 导出不包含应用保存的 API Key 或模型连接设置，导出内容包含对话正文。设置文件不另外创建备份，以免清除密钥后留下旧副本。

## 开发与打包

源码开发需要 Node.js 22.13 或更新版本：

```powershell
npm install
npm start
```

也可双击 `start-desktop.cmd`：有展开版时直接打开，否则从源码构建桌面版。

```powershell
npm test
npm run test:desktop
npm run dist:win
npm run dist:mac
npm run dist:linux
npm run release:checksums
```

`npm run test:desktop` 在独立临时数据目录中隐藏启动应用，检查 React 工作区、受限 preload、加密存储及关闭前保存，不操作用户窗口。模型测试使用模拟服务，不发送真实外部 AI 请求。

三个 `dist:*` 命令分别在 Windows、Apple Silicon Mac 和 Linux 构建机上运行；只运行所在平台对应的一条。`npm run dist` 也可按当前平台的默认目标打包。所有命令都设置 `--publish never`，不会自动发布到外部服务。Windows 生成 x64 NSIS 安装版及免安装版；Mac 生成 arm64 DMG 和 ZIP；Linux 生成 x64 DEB、RPM、AppImage 和 tar.gz。

构建机使用 `npm ci --include=optional` 安装锁定依赖；PDF 提取依赖 `@napi-rs/canvas` 原生模块，不能把 Windows 的 `node_modules` 复制到 Mac/Linux。Mac 需要 Xcode Command Line Tools，Linux 的 RPM 构建需要 `rpmbuild`。不要跳过可选依赖。图标已经包含在 `build/`；修改图标后，可用安装了 Pillow 的 Python 运行 `python scripts/make-icon.py` 同步生成 PNG、ICO 和 ICNS。

低内存 Linux 构建机可使用 `ELECTRON_BUILDER_COMPRESSION_LEVEL=6 npm run dist:linux -- --config.rpm.compression=gzip`，降低 tar.gz 和 RPM 压缩所需的资源；本次 Linux 构建采用这一设置。AppImage 使用固定的 static runtime 1.0.3，并通过 `build/after-pack.mjs` 保留默认 sandbox，不使用打包器自动添加的 `--no-sandbox`。

各平台都应执行单元测试，并用 `node scripts/desktop-smoke.mjs <打包后的可执行文件>` 检查真实包的 React 工作区、PDF 导入、系统密钥存储及退出保存。Mac 的可执行文件位于 `release/mac-arm64/枝间.app/Contents/MacOS/枝间`；Linux 位于 `release/linux-unpacked/branch-local`。Linux GUI 检查需要显示服务、系统密钥存储和可用的 Chromium sandbox。完成后将安装包汇集到 `release/`，运行 `npm run release:checksums` 生成校验文件。

当前未配置发行用代码签名证书；Mac 配置中的 `identity: "-"` 表示 ad hoc 签名。正式公证发行时应改用自己的 Developer ID 和公证凭据。跨平台构建约束见 [electron-builder 官方说明](https://www.electron.build/docs/features/multi-platform-build/)。

保留的网页开发模式为 `npm run dev`；`npm run web` 可启动旧式网页服务。它们只是开发选项，桌面版不依赖它们。桌面数据目录可通过 `BRANCH_LOCAL_USER_DATA` 指定。

目前支持本地文字型材料和可追溯结论；尚未实现扫描 PDF OCR、网页抓取、多人协作和云同步。
